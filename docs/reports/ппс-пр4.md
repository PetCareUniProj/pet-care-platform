# **1\. Вступ** {#1.-вступ}

Системні вимоги встановлюють обмеження на вибір архітектури, технологій та інструментів, а також описують необхідне апаратне та програмне оточення.  
Згідно з класифікацією SWEBOK (Software Engineering Body of Knowledge), системні вимоги (System Requirements) визначають зовнішні умови виконання системних функцій та обмеження на створення продукту. Вони є фундаментом для прийняття архітектурних рішень та планування інфраструктури.  
Для "Pet Connect", що включає в себе веб\-сайт, мобільний застосунок та складну серверну частину, визначення системних вимог є критично важливим для забезпечення стабільної, продуктивної та надійної роботи. У даній практичній роботі будуть детально описані вимоги до апаратного та програмного забезпечення, а також до зовнішніх інтерфейсів системи.

# **2\. Вимоги до апаратного забезпечення** {#2.-вимоги-до-апаратного-забезпечення}

Цей розділ визначає мінімальні та рекомендовані характеристики фізичного та віртуального "заліза", необхідного для стабільної роботи всіх компонентів системи "Pet Connect" — як на стороні сервера, так і на стороні кінцевих користувачів.

## **2.1. Вимоги до клієнтського обладнання (для користувачів)** {#2.1.-вимоги-до-клієнтського-обладнання-(для-користувачів)}

**2.2.1. Для мобільного застосунку "Pet Connect"**  
Застосунок повинен коректно функціонувати на смартфонах з наступними мінімальними характеристиками:

* Оперативна пам'ять (RAM): 3 ГБ.  
* Вбудована пам'ять: 100 МБ вільного місця для встановлення та зберігання кешованих даних.  
* Камера: Наявність камери для фотографування домашнього улюбленця.  
* Обґрунтування: Ці вимоги відповідають характеристикам більшості сучасних смартфонів середнього класу, що забезпечує широке охоплення аудиторії.

**2.2.2. Для веб\-сайту**  
Веб-сайт повинен бути доступним для перегляду та використання з будь-якого настільного комп'ютера, ноутбука, планшета або смартфона, здатного запустити сучасний веб\-браузер.   
Специфічних вимог до апаратного забезпечення клієнта не висувається, окрім наявності стабільного інтернет-з'єднання.

# **3\. Вимоги до програмного оточення** {#3.-вимоги-до-програмного-оточення}

Цей розділ визначає програмне забезпечення, яке є необхідним для розробки, розгортання та коректної роботи всіх компонентів екосистеми "Pet Connect". Ці вимоги є обов'язковими для забезпечення сумісності, стабільності та безпеки платформи.

## **3.1. Вимоги до серверного програмного оточення** {#3.1.-вимоги-до-серверного-програмного-оточення}

**3.1.1. Серверна операційна система**  
Усі серверні компоненти системи повинні працювати під управлінням операційної системи сімейства Linux.  
Версія: Ubuntu 22.04 LTS або новіша версія з довгостроковою підтримкою.  
**3.1.2. Середовище виконання (Runtime Environment)**  
Система повинна підтримувати та використовувати наступні середовища виконання для своїх мікросервісів:

1. .NET 9\.  
2. Node.js 20.x LTS або новіша версія.

**3.1.3. Веб-сервер**  
Для обробки вхідних HTTP-запитів, проксіювання на сервери додатків та роздачі статичного контенту повинен використовуватися веб\-сервер Nginx.

## **3.2. Вимоги до системи управління базами даних (СУБД)** {#3.2.-вимоги-до-системи-управління-базами-даних-(субд)}

**3.2.1. Основна СУБД**  
В якості основної реляційної бази даних для зберігання постійних даних (профілі користувачів, дані тварин, замовлення, каталог) повинна використовуватися PostgreSQL версії 16 або новішої.  
**3.2.2. Сховище для кешування**  
Для кешування даних, що часто запитуються, та зберігання тимчасових даних (наприклад, сесій користувачів, вмісту кошика) повинна використовуватися in-memory база даних Redis.

## **3.3. Вимоги до клієнтського програмного оточення** {#3.3.-вимоги-до-клієнтського-програмного-оточення}

**3.3.1. Для веб\-сайту**  
Веб-сайт повинен коректно функціонувати в останніх двох мажорних версіях наступних веб\-браузерів:

1. Google Chrome  
2. Mozilla Firefox  
3. Safari  
4. Microsoft Edge

**3.3.2. Для мобільного застосунку**  
Мобільний застосунок повинен бути сумісним з наступними операційними системами:

1. iOS: Дві останні мажорні версії.  
2. Android: Версії, починаючи з 12 (API level 31).

## **3.4. Вимоги до середовища розробки та розгортання** {#3.4.-вимоги-до-середовища-розробки-та-розгортання}

**3.4.1. Система контролю версій**  
Уся розробка повинна вестися з використанням розподіленої системи контролю версій Git.  
**3.4.2. Контейнеризація**  
Усі серверні мікросервіси повинні бути запаковані в Docker-контейнери.

# **4\. Вимоги до зовнішніх інтерфейсів** {#4.-вимоги-до-зовнішніх-інтерфейсів}

Цей розділ описує стандарти та протоколи, за якими система "Pet Connect" взаємодіє з клієнтськими додатками та зовнішніми сервісами.

##  **4.1. API для клієнтських додатків (Client API)** {#4.1.-api-для-клієнтських-додатків-(client-api)}

Взаємодія між мобільним застосунком, веб\-сайтом та серверною частиною повинна відбуватися через RESTful API.

Усі дані, що передаються через RESTful API, повинні бути у форматі JSON.

Все API повинно бути задокументовано згідно зі стандартом OpenAPI 3.0 (Swagger).

Для швидкої комунікації між мікросервісами, зокрема для управління кошиком, може використовуватися протокол gRPC.

## **4.2. Інтерфейс платіжної системи** {#4.2.-інтерфейс-платіжної-системи}

Система повинна інтегруватися з API платіжного шлюзу (LiqPay) за протоколом HTTPS для безпечної обробки онлайн-платежів.

## **4.3. Інтерфейс для взаємодії сервісів** {#4.3.-інтерфейс-для-взаємодії-сервісів}

Для асинхронної взаємодії між мікросервісами (наприклад, для обробки замовлень) повинен використовуватися брокер повідомлень RabbitMQ з протоколом AMQP.

# **5\. Вимоги до операційного середовища**  {#5.-вимоги-до-операційного-середовища}

Цей розділ визначає вимоги до процесів розгортання, моніторингу та підтримки екосистеми "Pet Connect" в експлуатації.

## **5.1. Розгортання (Deployment)** {#5.1.-розгортання-(deployment)}

Усі компоненти серверної частини системи повинні бути контейнеризовані за допомогою Docker.  
Для управління та оркестрації контейнерів у production-середовищі повинна використовуватися система Kubernetes.  
Процес розгортання нової версії на тестове та робоче середовища повинен бути автоматизованим за допомогою системи безперервної інтеграції та доставки (CI/CD).

## **5.2. Резервне копіювання та відновлення** {#5.2.-резервне-копіювання-та-відновлення}

Повинна бути налаштована процедура автоматичного щоденного резервного копіювання основної бази даних (PostgreSQL).
