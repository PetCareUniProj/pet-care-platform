1. # **Вступ** {#вступ}

Дана практична робота присвячена ключовому етапу життєвого циклу розробки програмного забезпечення – детальному плануванню проекту. Метою роботи є застосування теоретичних знань та практичних навичок управління проектами з використанням сучасного хмарного інструменту Wrike. Цей етап є продовженням попередньої роботи, де були визначені функціональні та системні вимоги до проекту "Pet Connect", і слугує мостом для перетворення цих вимог на структурований, керований та вимірюваний план дій.

Вибір Wrike як інструменту для планування обумовлений вимогами завдання та його широкими можливостями: централізоване управління завданнями, гнучкі інструменти візуалізації, наприклад канбан-дошки та діаграми Ганта, функції для командної співпраці та моніторингу прогресу. 

2. # **Створення та деталізація проекту**  {#створення-та-деталізація-проекту}

Робота розпочалася зі створення нового проекту "Pet Connect" в особистому просторі Wrike. Для забезпечення повноти та логічної послідовності, вся проектна діяльність була розділена на п'ять фундаментальних етапів, кожен з яких був детально декомпонований на конкретні завдання та підзавдання.

  2. ## **Планування (Документація та управління)** {#планування-(документація-та-управління)}

  3. ## **Розробка** {#розробка}

Цей етап розробки  є найбільш об'ємним і був розділений на три паралельні напрямки: Backend частина, мобільний застосунок та вебзастосунок.

* **Розробка Backend (мікросервіси):** кожен мікросервіс був спроектований для виконання чіткої бізнес-функції, забезпечуючи гнучкість та незалежне масштабування:

  * **Сервіс автентифікації та авторизації (Auth Service):** це централізована система управління ідентифікацією на базі KeyCloak. Вона відповідатиме за реєстрацію, вхід, керування сесіями та визначення ролей (наприклад, "користувач", "адмін"), а також за захист API для мобільного та веб\-клієнтів.

    * Визначити та налаштувати ролі.

    * Налаштувати клієнтів (Clients) для додатків.

    * Розгорнути екземпляр KeyCloak.

    * Створити та налаштувати Realm.

  * **Сервіс замовлень (OrderingApi \- .NET):** цей сервіс керуватиме повним життєвим циклом замовлень. Він надасть функціонал для створення замовлень, їх оплати через інтегрований платіжний шлюз та перегляду історії замовлень користувачем. Також він буде асинхронно сповіщати інші частини системи про нові замовлення через RabbitMQ.

    * Спроектувати та реалізувати схему бази даних.

    * Реалізувати API для створення замовлення.

    * Інтегрувати платіжний шлюз.

    * Реалізувати API для отримання історії замовлень.

    * Налаштувати публікацію подій у RabbitMQ.

  * **Сервіс каталогу товарів (CatalogApi \- .NET):** він слугуватиме єдиним джерелом інформації про товари. Для клієнтів буде реалізовано публічне API з пошуком, фільтрацією та пагінацією. Для адміністраторів буде створено окремий, захищений (через KeyCloak) набір CRUD-ендпоінтів для керування асортиментом.

    * Спроектувати та реалізувати схему бази даних.

    * Реалізувати публічні API ендпоінти для каталогу.

    * Реалізувати логіку пошуку, фільтрації та пагінації.

    * Реалізувати адміністративні CRUD API ендпоінти.

    * Налаштувати інтеграцію з KeyCloak.

  * **Сервіс кошика (BasketApi \- .NET):** цей сервіс буде керувати тимчасовими кошиками користувачів, використовуючи для зберігання Redis. Він надаватиме REST API для клієнтських додатків (додати/видалити товар) та gRPC для швидкої внутрішньої комунікації з іншими сервісами (наприклад, сервісом замовлень під час оформлення).

    * Налаштувати проєкт та підключення до Redis.

    * Реалізувати REST API для управління кошиком.

    * Реалізувати gRPC ендпоінти.

  * **Сервіс обробки фонових завдань (Processor Services):** цей компонент відповідатиме за асинхронну обробку завдань, які не потребують негайної відповіді користувачу. Він буде "слухати" повідомлення з RabbitMQ та виконувати логіку, наприклад, фінальну обробку замовлення (OrderProcessor) або верифікацію платежів (PaymentProcessor) після їх створення.

    * Налаштувати RabbitMQ.

    * Реалізувати сервіс обробки замовлень (OrderProcessor).

    * Реалізувати сервіс обробки платежів (PaymentProcessor).

  * **Сервіс підписок (SubscriptionApi \- Node.js/NestJS):** цей сервіс дозволить користувачам керувати своїми регулярними підписками (наприклад, щомісячна доставка корму). Він матиме CRUD API для управління підписками та фоновий процес, який автоматично створюватиме нові замовлення в системі відповідно до графіку підписки.

    * Спроектувати та реалізувати схему бази даних.

    * Реалізувати CRUD API для управління підписками.

    * Реалізувати фоновий процес для створення замовлень.

* **Розробка Frontend (вебзастосунок):** це завдання, пов'язані з розробкою повноцінного клієнтського веб\-додатку, який надасть користувачам графічний інтерфейс для взаємодії з усіма сервісами "Pet Connect". Цей додаток буде включати інтернет-магазин та особистий кабінет.

  * 1\. UI/UX Дизайн та Прототипування (Figma)

    * Створити дизайн-систему.

    * Розробити макети для публічної частини (Інтернет-магазин).

    * Розробити макети для особистого кабінету.

    * Створити інтерактивний прототип.

  * 2\. Базове налаштування проєкту та верстка

    * Ініціалізувати frontend-проєкт.

    * Зверстати основні UI компоненти.

    * Зверстати сторінки публічної частини.

    * Зверстати сторінки особистого кабінету.

  * 3\. Інтеграція з Backend та реалізація логіки

    * Інтегрувати логіку автентифікації.

    * Інтегрувати сервіс каталогу.

    * Інтегрувати сервіси кошика та замовлень.

    * Реалізувати логіку особистого кабінету.

* **Розробка мобільного застосунку:** це завдання, пов'язані зі створенням нативного мобільного застосунку, який надасть користувачам ключовий функціонал для догляду за домашніми улюбленцями. Цей додаток буде зосереджений на персоналізованих інструментах, таких як управління профілями тварин, календар подій та нагадувань, а також інноваційний помічник.

  * 1\. UI/UX Дизайн та Прототипування (Figma)

    * Створення дизайн-системи та UI Kit.

    * Проектування сценарію онбордингу та автентифікації.

    * Проектування основного функціоналу.

    * Проектування інтеграції з магазином.

    * Проектування інноваційного помічника.

    * Створення інтерактивного клікабельного прототипу.

  * 2\. Базове налаштування проєкту та архітектура

    * Ініціалізація та налаштування середовища.

    * Налаштування навігації.

    * Налаштування управління станом (State Management).

    * Створення сервісного шару.

    * Створення UI Kit у коді.

  * 3\. Реалізація функціоналу МVР

    * Реалізація автентифікації.

    * Реалізація управління профілями тварин.

    * Реалізація календаря та нагадувань.

    * Реалізація інноваційного помічника.

6. # **Висновки** {#висновки}

В ході виконання даної практичної роботи було проведено комплексне та глибоке планування проекту "Pet Connect" з використанням інструментарію Wrike. Детальна декомпозиція робіт, призначення відповідальних, візуалізація процесів за допомогою канбан-дошки та діаграми Ганта, а також налаштування моніторингу та звітності дозволили створити не просто формальний план, а реалістичну та гнучку дорожню карту для розробки продукту.

Практика показала, що застосування систем управління проектами, таких як Wrike, є невід'ємною частиною сучасної програмної інженерії. Це дозволяє мінімізувати ризики, підвищити прозорість та керованість процесу розробки, а також забезпечити ефективну комунікацію та співпрацю в команді, що є критично важливими факторами для успішної реалізації складних проектів.
