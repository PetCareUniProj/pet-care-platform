## 2. Архітектура системи "Pet Connect"

Система "Pet Connect" є клієнт-серверною платформою для догляду за домашніми тваринами, що включає:

- **Мобільний додаток** (React Native) для власників тварин
- **Веб-додаток** (NestJS) інтернет-магазину
- **Мікросервісну архітектуру** на backend (.NET 9, NestJS)
- **Інфраструктуру** (PostgreSQL, Redis, RabbitMQ, Keycloak)

Система реалізує комплексний підхід до догляду за тваринами: від створення профілів та нагадувань до онлайн-покупок ветеринарних товарів.

3. **Менеджер магазину (Персонал)**
   - Працівник ветеринарної клініки

   - Повний доступ до всіх функцій системи

   - Специфічний актор для мобільного додатку
   - Фокус на управлінні профілями тварин та нагадуваннями

#### Основні прецеденти (use cases):

**Для всіх користувачів:**
- Перегляд каталогу товарів
- Пошук та фільтрація товарів
- Перегляд детальної інформації про товар

**Для клієнтів:**
- Реєстрація та авторизація
- Управління персональними даними

- Управління профілями тварин
- Створення та управління нагадуваннями

**Для персоналу:**
- Управління каталогом товарів (створення, редагування, видалення)
- Управління категоріями та брендами
- Обробка замовлень (зміна статусів)
- Управління запасами товарів

**Для адміністраторів:**
- Управління обліковими записами персоналу
- Перегляд аналітичних звітів
- Генерація фінансових звітів

#### Ключові зв'язки:
- `<<include>>`: Оформлення замовлення включає додавання товарів до кошика

### 3.3. Statechart Diagram (діаграма станів)

**Файл:** `diagrams/03-statechart.puml`  
**Тема:** Оранжева (стани та переходи)  
**Кольорова схема:** #FFE6CC (основні стани), #FFCC99 (початковий), #FFB366 (кінцевий)

#### Стани замовлення:

1. **Draft** (Чернетка)
   - Початковий стан при створенні замовлення
   - Замовлення не підтверджено, може бути змінено або скасовано

2. **Submitted** (Подано)
   - Клієнт підтвердив замовлення
   - Очікує обробки системою

3. **AwaitingValidation** (Очікує валідації)
   - Система перевіряє наявність товарів на складі
   - Критичний стан: можливе скасування при недостатніх запасах

4. **StockConfirmed** (Запаси підтверджені)
   - Всі товари зарезервовані на складі
   - Очікується оплата від клієнта

5. **Paid** (Оплачено)
   - Оплата успішно отримана
   - Можна переходити до відправки

6. **Shipped** (Відправлено)
   - Замовлення передано службі доставки
   - Очікується отримання клієнтом

7. **Cancelled** (Скасовано)
   - Замовлення скасовано (клієнтом або системою)
   - Кінцевий стан, кошти повернуті

#### Переходи між станами:

**Автоматичні переходи:**
- Draft → Submitted (submitOrder())
- Submitted → AwaitingValidation (startValidation())

**Умовні переходи:**
- AwaitingValidation → StockConfirmed (confirmStock())
- AwaitingValidation → Cancelled (stockRejected())
- StockConfirmed → Paid (processPayment())
- Paid → Shipped (shipOrder())

**Скасовуючі переходи:**
- Будь-який стан → Cancelled (cancelOrder())

#### Бізнес-логіка станів:

**Draft стан:**
- Тимчасове зберігання незавершеного замовлення
- Можливість редагування складу замовлення

**AwaitingValidation стан:**
- Перевірка ціни та наявності товарів
- Резервування товарів на складі
- Можливе автоматичне скасування при проблемах

**StockConfirmed стан:**
- Товари фізично зарезервовані
- Час на оплату обмежений
- Неможливо скасувати після оплати

- Розділення відповідальностей між сервісами
- Асинхронна комунікація через Event Bus
- Незалежне масштабування компонентів

**Domain-Driven Design:**
- Чітке розділення доменів (Catalog, Ordering)
- Агрегатні корені та value objects
- Бізнес-логіка в доменних моделях

**Інфраструктура:**
- Контейнеризація через Docker
- Оркестрація через Kubernetes
- Балансування навантаження через Nginx

### 4.3. Переваги використання PlantUML

1. **Версійонування:** Діаграми як текст в Git
2. **Швидкість розробки:** Зміни без графічних редакторів
3. **Сумісність:** Підтримка різних форматів виводу
4. **Стилізація:** Багатий синтаксис для візуального оформлення

### 4.4. Рекомендації для подальшої розробки

1. **Додавання Sequence Diagram** для інших сценаріїв (створення нагадувань, управління підписками)
2. **Розширення Class Diagram** новими доменами (Subscription, Notification)
3. **Створення Package Diagram** для логічної структури пакетів
4. **Розробка Communication Diagram** для детального аналізу взаємодій
